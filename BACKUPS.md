# Backup locations

## v1 — final state before v2 work

The full v1 codebase (the live `card-pricer-60qq.onrender.com` deploy) is preserved at git tag **`v1-final`** (alias **`v1.70`**) on commit `80448c0`.

```bash
# Inspect v1 without touching main
git show v1-final:public/index.html | head -40

# Check out v1 in a worktree (won't disturb main)
git worktree add /tmp/v1-snapshot v1-final

# Restore v1 wholesale (rolls main back — destructive, requires force-push)
git checkout main
git reset --hard v1-final          # CAREFUL — wipes v2 work locally
git push --force-with-lease        # CAREFUL — wipes v2 work on GitHub
```

Render's auto-deploy currently builds from `main` HEAD using `server.js` + `public/` at the repo root — those v1 files are still present and unchanged in `main` after v2 work began. v1 keeps running while v2 builds in `v2/`. Cutover happens by pointing Render at the v2 build (or by adding a second Render service).

- Build: `npm install && npm run prestart`.
- Start: `npm run start` → `node server.js`.
- Static files: `public/` directory.
- Environment variables: see DEPLOY.md.

## In-memory data files (not in git)

- `data/card-db.json` — local card database (~50k entries, regenerated from pokemontcg.io on first boot).
- `data/card-prices.json` — price snapshot for the arbitrage tool (regenerated by admin "Refresh prices").

These are runtime caches, not source. v2 moves card-prices into the Postgres `card_prices` table — a one-time migration script runs at v2 cutover.
